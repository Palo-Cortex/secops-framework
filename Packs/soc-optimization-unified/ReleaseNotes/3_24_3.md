##### SOCFrameworkActions_V3

CrowdStrike containment and de-containment now pass an argument the commands
accept.

```
before   cs-falcon-contain-host           agent_id = ${...Artifacts.EndPointID}
         cs-falcon-lift-host-containment  agent_id = ${...Artifacts.EndPointID}

after    cs-falcon-contain-host           ids      = ${...Artifacts.Endpoint.AgentID}
         cs-falcon-lift-host-containment  ids      = ${...Artifacts.Endpoint.AgentID}
```

Neither command accepts `agent_id`. Both declare `ids` as required. Every
CrowdStrike `soc-isolate-endpoint` and `soc-deisolate-endpoint` dispatch
therefore failed on a missing required argument — and because `agent_id`
resolved to a non-empty value, the empty-argument guard added in 3.24.1 could
not skip it either: the action dispatched and errored.

Argument names were read from the CrowdStrike Falcon integration's own command
spec on a live tenant, not from documentation or memory.

This completes the move to the agent ID across the CrowdStrike branch. 3.24.2
switched endpoint enrichment to `ids`; containment now matches, so enrichment,
containment and de-containment all resolve the same
`Artifacts.Endpoint.AgentID`.

Audited at the same time and confirmed correct, so unchanged:
`soc-block-indicators` (`cs-falcon-upload-custom-ioc`), and the five
`cs-falcon-run-command` actions — `soc-kill-process`, `soc-delete-file`,
`soc-remove-file`, `soc-remove-persistence`, `soc-file-exists`.
