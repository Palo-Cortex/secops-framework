#### Lists

##### SOCFrameworkActions_V3

Every vendor response is now checked against the command the vendor defines. The responses below
named an argument the command does not take, left out a required one, or used a value it does not
accept, so each would have failed the first time it ran live.

- **Microsoft Defender**
  - `soc-quarantine-files`, `soc-remove-file`, `soc-remove-persistence`: `machine_ids` and
    `file_hashes` are now `machine_id` and `file_hash`.
  - `soc-quarantine-files`, `soc-remove-file`, `soc-remove-persistence`, `soc-deisolate-endpoint`,
    `soc-file-exists` and `soc-kill-process` now send the `comment` the commands require.
  - `soc-block-indicators`: `title` and `description` are now `indicator_title` and
    `indicator_description`.
  - `soc-block-indicators`, `soc-block-network-indicator`: the block action is `Block`;
    `AlertAndBlock` is not a value the command accepts.
  - `soc-kill-process`: `script_name` and `args` are now `scriptName` and `arguments`. The script is
    one the customer uploads to the live response library, so `scriptName` is a tenant setting: the
    response skips with "not configured" until it is set in `SOCFWTenantConfig`.
- **Cortex Core - IR**, `soc-remove-persistence`: the command takes a script's id, not its name.
  `script_uid` is a tenant setting and the response skips until it is set.
- **Active Directory**
  - `soc-enable-user`: `sAMAccountName` is now `username`.
  - `soc-reset-password`: now expires the password with `ad-expire-password`, so the user sets a new
    one at next logon, as the Okta response does. It used to call `ad-set-new-password` with a fixed
    literal password.
- **Panorama**, `soc-block-network-indicator`: `address` is now `ip_netmask`.
- **Mimecast**
  - `soc-block-sender`: sends the sender as an individual address (`fromType`, `fromValue`) to
    everyone (`toType`).
  - `soc-quarantine-email`: `id` is now `ids`; `reason` is not an argument of the command.
- **Okta IAM**, `soc-enrich-user`: `user-profile` is sent as the profile object the command takes.
- **Cisco Umbrella**, `soc-enrich-domain`: `name` is now `domain`.
- **Google Workspace**, `soc-enrich-user`: `user-key` is now `user`.
- **Gmail**, `soc-retract-email`: `user_id` and `message_id` are now `user-id` and `message-id`.
- **Trend Micro Vision One**, `soc-enrich-endpoint`: drops `query_op`, which the command does not take.
- **Recorded Future**, `soc-enrich-ioc`: `entity_type` is `ip`; `indicator` is not a type the command
  accepts.
- **CrowdStrike Falcon Sandbox**, `soc-detonate-file`: `environment_id` is the full value the command
  expects, `160: Windows 10 (64-bit)`.

Removed, because they cannot work as written:

- `soc-retract-email` and `soc-search-and-delete-email`, O365 Compliance:
  `o365-sc-compliance-search-purge` is not a command of any integration.
- `soc-quarantine-email`, Trend Micro Vision One: the command requires the message's delivery time,
  which the framework does not collect.
- `soc-detonate-file`, WildFire v2 upload and Joe Security: both upload a file from a War Room entry,
  and the framework has only the file's path on the endpoint. Hash-based detonation (WildFire
  verdict, CrowdStrike Sandbox) is unchanged.

##### SOCExecutionList_V3

- Removed. It routed the phase playbooks of `soc-framework-nist-ir`, the non-AI NIST IR lifecycle, which
  is retired; only those playbooks read it. A tenant that has the list keeps it until the pack is
  uninstalled.
