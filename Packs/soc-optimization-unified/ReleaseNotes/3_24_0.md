#### Scripts

##### SOCFWElevateCase

New. Stars a case when the AI assessment warrants an analyst.

The conditions are data, not code: `phases.triage.elevate` in `SOCFrameworkPhasePolicy_V3`
carries a rule list, and any match stars the case. Ships with one conservative rule — a
malicious verdict at high confidence — measured against a production SOC rather than a
demo tenant, where it selects roughly 3% of assessed issues.

Idempotent on the case's real starred state rather than a flag, because every issue in a
case runs this: a 63-issue case produces one star, not 63 dispatches. Starring is
case-level, so an issue with no case yet records the gap instead of acting. The framework
never un-stars — a star is also the backstop that stops auto-triage closing a case.

##### SOCCommandWrapper

Platform actions now dispatch without a source vendor.

The wrapper resolves an action's implementation from the alert's source vendor and
refuses to fall back to "first available vendor", so it can never fire one vendor's
command at another vendor's host. Correct for vendor actions, but starring, severity and
closing are done by the platform and carry a single `Builtin` implementation that no
source vendor can satisfy — so they were skipped on every alert, recording a skip rather
than an error.

An action whose **only** implementation is `Builtin` now dispatches independently of the
source vendor. An action with `Builtin` plus vendor branches still routes by vendor.

**Check before upgrading:** this also un-skips `soc-close-issue`, which has the same
shape and is dispatched by `SOCFWCloseDecision`. Until now two things stopped it closing
anything — the vendor skip and shadow mode. After this upgrade only shadow mode does. If
`soc-close-issue` is set to `shadow_mode: false` on a tenant, auto-close begins working
there for the first time. Confirm that flag before upgrading a tenant where closing was
configured but never appeared to run.

Also accepts `issue_emergency`, `case_lifecycle`, `ai` and `framework` as action actors.
Previously anything unrecognised was recorded as `analyst`, so automated decisions were
attributed to a human in the execution dataset.

#### Lists

##### SOCFrameworkActions_V3

Adds `soc-star-case`, which stars the parent case through the platform's own
`setParentIncidentFields`. Ships shadowed for the automated actors, so nothing stars
automatically until it is deliberately enabled.

Adds `shadow_mode_by_actor` to the 17 response actions across endpoint, identity, email
and network, with every actor shadowed. Behaviour is unchanged; the surface is now
addressable so containment can be loosened one actor at a time.

##### SOCFrameworkPhasePolicy_V3

Adds the `phases.triage.elevate` block holding the starring rules.
