#### Scripts

##### SOCFWAnalystSelect

- New `cases` argument: `starred` (default) assigns only starred cases, `all` assigns every open
  case. Empty or any other value means `starred`, so a tenant whose `SOCOptimizationConfig_V3`
  lacks the setting gets the narrower default. **This changes the 3.31.0 behaviour**, which
  assigned every open case; set `AssignmentCases` to `all` to keep it.
- Load still counts every open case an analyst holds, starred or not, so the per-analyst cap is
  unchanged. An explicit `case_id` is assigned whether or not it is starred.

##### SOCFWHealthCheck

- New `Instance: <name>` checks, run in every mode, for the integration instances the framework
  calls by exact name: `socfw_ir_execution_writer`, `socfw_case_ledger_writer` and
  `Unit_42_Intelligence_SOCFW`. Missing or disabled is FAIL. When the brand exists under another
  name, the check names that instance so the fix is a rename. Before this, any enabled instance of
  the brand passed, so a renamed dataset writer showed green while every framework row failed to
  write.

#### Playbooks

##### JOB - SOCFW Analyst Assignment

- Passes `AssignmentCases` to `SOCFWAnalystSelect` as `cases`.

#### Lists

##### SOCOptimizationConfig_V3

- New `AssignmentCases` field in the `Analyst Assignment JOB` section: `starred` (default) or `all`.
