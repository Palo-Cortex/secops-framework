#### Scripts

##### SOCFWConfig

- New `command=assignment`: the analyst assignment settings in the tenant's own list, the same
  way `command=triage` works. `roles`, `groups`, `cases`, `domains`, `window`, `max_per_analyst`
  and `online_only`, any subset; `default` removes one; `none` for `roles` or `groups` turns that
  fallback off; dry run unless `apply=yes`; every change recorded as a `config_change` row.
  Values are checked before they are written, so a setting that would stop the JOB is refused.
  With no arguments it lists the settings with their source. Most customers set `groups` to their
  analyst group so the on-duty fallback is not the admin roles.
- `command=status` shows the assignment settings with their source.

##### SOCFWAnalystSelect, SOCFWOnDutySync

- Read the `assignment` section of `SOCFWTenantConfig` before the arguments the JOB passes from
  `SOCOptimizationConfig_V3`, so the list no longer has to be detached to change a setting, and a
  pack upgrade cannot undo a tenant's choice. The run output names the settings taken from the
  tenant.

- `SOCFWOnDutySync`: when the configured roles or groups match no tenant user, the role fallback
  now removes its own rows and reports nobody on duty, instead of keeping the previous fallback
  roster. A read failure still changes nothing. The schedule sources are unchanged: nobody on
  call from a schedule source still changes nothing.

- `SOCFWOnDutySync`: lookup writes retry once after 5 seconds. A manual run that overlaps the
  JOB's own sync was answered with HTTP 500 by the platform; both writes are idempotent.

##### SOCFWHealthCheck

- The roster warning names `!SOCFWConfig command=assignment groups=` as the fix.
