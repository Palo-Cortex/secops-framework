#### Scripts

##### SOCFWEmergencyResponse

- New. Contains an issue without waiting for its case to develop. When the issue matches
  an emergency policy, it runs the policy's containment actions through SOCCommandWrapper
  as the `issue_emergency` actor, each action once, so Shadow Mode decides whether they
  really run. Only containment actions run here; eradication and recovery wait for the
  case.
- A host action runs only on a host that is not protected and either is in
  `containable_hosts` (when set) or has a role in `containable_roles` (default
  workstation). The role is the first to answer: the tenant's role entries, the EDR, the
  operating system (macOS and Windows client editions read as workstation, Windows Server
  as server, Linux as unknown). An unknown role is never contained, so a domain
  controller or server is never isolated automatically.
- A host the EDR already reports contained or pending is not isolated again. After a real
  isolate the issue's `endpointisolationstatus` is set to `containment_pending`.
- Containment that was needed but did not happen - protected, role not containable, the
  vendor failed or the action skipped - stars the case and raises its severity to
  `escalate_severity` (default critical, raise only), as `automation`, so a person contains
  it by hand. A shadowed action is not escalated.
- Closes the issue as true positive, contained (`soc-close-issue-contained`, as
  `automation`) only when every action really ran or the EDR already reported the host
  contained. Otherwise it records what it would have done and leaves the issue open.
- Never acts on an issue the assessment says is already contained.
- Writes an `emergency_decision` row to the execution dataset every time, including when
  no policy matched, with what was blocked and why and what was escalated.

##### SOCFWConfig

- New `command=emergency`. With no arguments it lists every emergency policy - shipped and
  this tenant's - with what it matches, its gate, whether each action is live or simulated
  for `issue_emergency`, and the host settings.
- `policy=<label>` edits a shipped policy (only the fields given are stored) or adds a
  tenant policy. `rule_id` and `name_contains` are for tenant policies only. A policy takes
  containment actions only. `enabled=off` turns one off; `enabled=default` returns it to
  what shipped.
- Host and account settings for every policy: `protect` (never contained -
  `host:`, `ip:`, `cidr:`, `account:` or `list:<XSIAM list>` entries), `containable_hosts`,
  `containable_roles` (`any` turns the role check off), `role` (`host:<pattern>:<role>`)
  and `escalate_severity`. Each replaces the shipped value; `default` returns it.
- Every change is a dry run unless `apply=yes` and is recorded as a `config_change` row.
- Every command now refuses an argument that belongs to another command instead of
  ignoring it. Argument descriptions start with the commands they apply to.
- `status` adds a one-line emergency response summary, and no longer lists an action's
  `target=` argument as a customer value.

##### SOCCommandWrapper

- New `target` argument: name what to act on from the War Room, replacing the issue's
  artifact. `!SOCCommandWrapper action=soc-block-domain target=bad.example,other.example`
  blocks those domains on every configured vendor (ThreatStop and Zscaler), one call per
  domain, even on an issue that carries no domain.
- Comma-separated for more than one; blanks and repeats are dropped.
- Works only on actions that name what they act on (a `target_arg`). Other actions, such as
  `soc-isolate-endpoint`, refuse `target` with an error rather than ignoring it.
- Shadow Mode, tenant config and the not-configured skip apply as before. The dataset row's
  `action_target` records the target given.
- A vendor branch can now say where its vendor reports an endpoint's containment state and
  role. The wrapper returns them on its record (`status`, `role`) and refreshes
  `SOCFramework.Endpoint.containment_status` and `SOCFramework.Endpoint.role`, except for a
  layout render. A value the map does not name reads as unknown and is never written.

#### Lists

##### SOCFrameworkPhasePolicy_V3

- New `phases.triage.emergency`: three default policies, each malicious at high
  confidence, matching the issue's product category. `identity_compromise` (clear
  sessions, revoke tokens), `endpoint_execution` (executed: isolate) and `email_delivered`
  (delivered or executed: retract, block the domain). Host settings `containable_roles`
  (workstation), `containable_hosts`, `protect`, `role` (empty) and `escalate_severity`
  (critical). Every action ships shadowed, so in a PoV this only records.

##### SOCFrameworkActions_V3

- New `soc-close-issue-contained`: closes the issue with reason "Resolved - True Positive"
  (stored as `RESOLVED_TRUE_POSITIVE`) and notes naming what was contained. Shadowed for
  every actor, separate from `soc-close-issue` so closing benign issues and closing
  contained ones are turned on independently.
- New `soc-raise-case-severity`: sets the case's severity through `setParentIncidentFields`
  `manual_severity`, the value given with `target=`. Shadowed for every actor.
- `soc-enrich-endpoint` reads containment state for Cortex Core (`is_isolated`), CrowdStrike
  (`CrowdStrike.Device.Status`) and SentinelOne (`NetworkStatus`), and role for Cortex Core
  (`endpoint_type`) and SentinelOne (`MachineType`). Defender and Trend Micro report no
  isolation state on their lookups.
- The Okta v2 identity containment, eradication and recovery rows ship an empty `using`, so
  a tenant with more than one Okta instance can set which one runs them:
  `!SOCFWConfig command=set vendor="Okta v2" arg=using value=<instance> apply=yes`.

##### SOCProductCategoryMap_V3

- Added `ds_zscaler_nssweblog` (Zscaler web-proxy logs through NSS, tag `DS:Zscaler/NSSWeblog`),
  mapped exactly like `ds_zscaler_zia`: category Network, responding vendor Zscaler, indicator
  enrichment through Unit 42 Intelligence. Before, the key was not in the map, so those issues got
  an inferred category and no vendor: routed actions such as `soc-block-network-indicator` skipped
  with "no implementation for source vendor". `soc-block-domain` was not affected (it fans out to
  every configured vendor).
