#### Scripts

##### SOCCommandWrapper

- New `target` argument: name what to act on from the War Room, replacing the issue's
  artifact. `!SOCCommandWrapper action=soc-block-domain target=bad.example,other.example`
  blocks those domains on every configured vendor (ThreatStop and Zscaler), one call per
  domain, even on an issue that carries no domain.
- Comma-separated for more than one; blanks and repeats are dropped.
- Works only on actions that name what they act on (a `target_arg`). Other actions, such as
  `soc-isolate-endpoint`, refuse `target` with an error rather than ignoring it.
- Shadow Mode, tenant config and the not-configured skip apply as before. The dataset row's
  `action_target` records the target given.

#### Lists

##### SOCProductCategoryMap_V3

- Added `ds_zscaler_nssweblog` (Zscaler web-proxy logs through NSS, tag `DS:Zscaler/NSSWeblog`),
  mapped exactly like `ds_zscaler_zia`: category Network, responding vendor Zscaler, indicator
  enrichment through Unit 42 Intelligence. Before, the key was not in the map, so those issues got
  an inferred category and no vendor: routed actions such as `soc-block-network-indicator` skipped
  with "no implementation for source vendor". `soc-block-domain` was not affected (it fans out to
  every configured vendor).
