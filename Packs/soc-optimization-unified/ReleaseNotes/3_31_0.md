#### Scripts

##### New: SOCFWOnDutySync

- Keeps the `socfw_on_duty` lookup in step with who the customer's schedule sources say is on
  duty, through the new `soc-sync-on-duty` action. Every source with a configured integration
  answers; PagerDuty v2 ships and needs `schedule_ids` (`!SOCFWConfig command=set`).
- `analysts=` is the manual roster for a tenant with no schedule system:
  `!SOCFWOnDutySync analysts="a@example.com,b@example.com"`.
- With no schedule source set up, tenant users with an `AssignmentRoles` role or in an
  `AssignmentGroups` group are on duty. A source that is set up but fails does not trigger this,
  and the rows are removed once a schedule source answers.
- Creates the lookup on first run and never wipes it. Each source replaces only its own rows; a
  source that errors or returns nobody changes nothing. Emails that are not tenant users are
  reported and left out. Every sync is recorded as an `on_duty_sync` row.

##### New: SOCFWAnalystSelect

- Gives unassigned open cases an owner from the analysts on duty, least loaded first, through the
  new `soc-assign-case` action, which ships shadowed for every actor.
- Only cases created within `AssignmentWindow`, only analysts logged in now when
  `AssignmentOnlineOnly` is true, and never an analyst holding `AssignmentMaxPerAnalyst` open
  cases.
- Re-checks each case just before assigning it, and skips a case the framework assigned in the
  last 15 minutes, so overlapping runs never give one case two owners.
- Every decision is recorded as an `analyst_assignment` row with each on-duty analyst's load at
  that moment.

##### SOCCommandWrapper

- A `target` that is a JSON object is kept whole as one target instead of being split on its
  commas. Comma lists, lists and single values behave as before.

##### SOCFWConfig

- `command=job`, `owner` and `status` include the `SOCFW Analyst Assignment` JOB.
- The `pov`, `contain_identity_and_hosts` and `contain_all` modes turn the assignment JOB on and
  run `soc-assign-case` for real for `automation`; `star_and_triage` keeps it shadowed and off.

##### SOCFWHealthCheck

- With the assignment JOB on, a new "Analyst assignment roster" check warns when there is no
  roster, nobody is on duty, or everyone on duty comes only from the role and group fallback.

#### Playbooks

##### New: JOB - SOCFW Analyst Assignment

- Syncs the on-duty roster, then assigns unassigned cases. Ships off with a placeholder owner and
  runs every 5 minutes once on: `!SOCFWConfig command=job job="SOCFW Analyst Assignment" value=on owner=<email> apply=yes`.

#### Lists

##### SOCOptimizationConfig_V3

- New `Analyst Assignment JOB` section: `AssignmentDomains` (security), `AssignmentWindow`
  (24 hours), `AssignmentOnlineOnly` (true), `AssignmentMaxPerAnalyst` (20, or unlimited),
  `AssignmentMethod` (least_loaded), `AssignmentRoles` (Instance Administrator,Account Admin) and
  `AssignmentGroups` (empty). A tenant that detached this list keeps its copy; add the section
  there to change the defaults.

##### SOCFrameworkActions_V3

- New actions `soc-sync-on-duty` (read-only) and `soc-assign-case` (shadowed for every actor).

##### SOCFWConfigModes

- `soc-assign-case` and the assignment JOB added to every mode, as above.
