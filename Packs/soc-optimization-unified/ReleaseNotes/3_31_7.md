#### Scripts

##### SOCCommandWrapper

- A read-only action (enrichment or investigation phase) whose vendor command fails, for example
  with an HTTP 429 rate limit, no longer stops the playbook. The failure is still written to the
  War Room, the execution context and `xsiam_socfw_ir_execution_raw` (`action_status` = `failed`),
  the action's `UC.*` output keys are cleared, and the playbook continues without that result.
- Actions that change something (isolate, block, revoke, close) still stop the playbook when their
  command fails, so a failed containment is never read as one that ran.

##### SOCFWEmergencyResponse

- A `list:` entry in `protect` or `containable_hosts` that names a missing or unreadable XSIAM list
  now blocks the actions that setting guards and escalates the case. It used to read as an empty
  list, so a host or account the list protected could be contained.
- A `SOCFWTenantConfig` that exists but cannot be read (a read error, invalid JSON, not an object)
  now blocks every action of the matched policies and escalates the case. It used to read as no
  tenant settings, which dropped the tenant's protections and re-enabled policies it had turned off.
  A tenant with no `SOCFWTenantConfig`, or an empty one, still uses the shipped settings.
