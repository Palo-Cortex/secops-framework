
#### Correlation Rules

##### SOC Proofpoint TAP - Threat Detected All Alerts

- Severity now follows exposure instead of a fixed Medium. A permitted click is **High**. Delivered mail is **Medium** when the threat is an attachment or message text, or an inbound URL that URL Defense did not fully rewrite, and **Low** otherwise. Delivered mail is never High. Low issues do not join a case and do not start the automation.
- Email direction is set to `inbound` only when the `default_inbound` policy route or a click proves it, and is left empty otherwise. It was previously always `inbound`.
- The alert description now carries the classification, threat type, sender, subject, indicator and whether the URL was rewritten.
- Click events now populate threat type, classification, threat id and threat status from the click's own columns. These were empty on clicks.
- `action_file_sha256` now holds only the hash of the attachment Proofpoint judged malicious. It previously held every message-part hash, including the message body. `filehash` keeps the full list.
- The rule reads four more dataset columns: `policyRoutes`, `completelyRewritten`, `classification` and `threatID`.
- A tenant running its own copy of this rule gets none of this from the upgrade. Paste the new XQL into the copy.
