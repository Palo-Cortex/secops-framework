
#### Correlation Rules

##### SOC Proofpoint TAP - Threat Detected All Alerts

- Click events now produce URL and domain artifacts. `clicks permitted` and `clicks blocked` carry no `threatsInfoMap`; the clicked URL rides the top-level `url` column instead. The threat-URL, registered-domain, and DNS-name derivations read `threatsInfoMap` only, so a click produced an empty **socfwemailthreaturl**, **fw_url_domain**, and **dns_query_name** — leaving `actor_effective_username` as the sole grouping artifact on the one event that proves the user actually engaged with the threat.
- Added `effective_threat_url`, which resolves to the `threatsInfoMap` threat URL on message events and the top-level `url` on click events. **fw_url_domain**, **dns_query_name**, and **clickedurls** now derive from it.
- **socfwemailthreaturl** falls back to the top-level `url` when `threatsInfoMap` yields no threat URL.
- A permitted click now groups on the same registered domain as the message that delivered it, and as the endpoint that subsequently resolved or fetched that domain.
