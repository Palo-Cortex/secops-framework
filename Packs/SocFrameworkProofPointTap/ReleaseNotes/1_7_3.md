## [1.7.3] - October 2026

### Fixed

#### SOC Proofpoint TAP - Threat Detected All Alerts — realigned onto XSIAM/SOCFW issue fields

The rule mapped 27 `proofpointtap*` alert fields into issue fields that nothing
in this repository creates. No `proofpointtap*` incident field has ever shipped
in any pack or release — the 1.5.6 release zip contains the same eight
forensic/HTTP fields as today. Those fields exist only on tenants where someone
created them by hand, so on any other tenant the rule failed with
"references at least one field that no longer exists".

The 27 are resolved as follows:

- **7** were exact duplicates of a surviving mapping (`campaignId` fed both
  `proofpointtapcampaignid` and `socfwemailcampaignid`, and so on) and are
  dropped.
- **16** were referenced only by the two layouts, which are removed with them.
- **4** are consumed by the NIST IR playbooks and are repointed to fields that
  carry the same value, each confirmed against real tenant rows:

| was | now | note |
|---|---|---|
| `proofpointtapmessageid` | `emailmessageid` | same source, `messageID` |
| `proofpointtapsmtpsender` | `emailsender` | same source, `sender` |
| `proofpointtapsuspiciousurl` | `socfwemailthreaturl` | playbook already applies `FirstArrayElement` |
| `proofpointtapthreatinfomap` | `socfwemailthreaturl` | playbook read `.threat` from it |

Alert fields go from 101 to 74. All four grouping pivots are preserved
(`actor_effective_username`, `user_principal`, `action_local_ip`,
`action_file_sha256`) and all twelve `socfwemail*` contract fields are intact.

#### `_alert_data` reads moved to `_raw_json`

`_alert_data` is platform-injected and cannot be a column on a
collector-fed dataset — the HTTP Collector strips underscore-prefixed fields.
Declaring it in `_schema.json` does not help either; the install still fails
with 101704. Its three reads now resolve through `_raw_json`, keeping the
existing literal fallbacks, so the dynamic value survives where the collector
provides it and the fallback applies where it does not.

### Changed

#### Layouts removed

Vendor packs ship rules. The two Proofpoint layouts are removed; the 16
layout-only `proofpointtap*` mappings go with them.

The eight incident fields remain for now: four (`forensic*markdown`) are
consumed by `SOC_Email_Forensics_Evaluation_V3` in `soc-framework-nist-ir` and
belong in that pack. Relocating them is separate work.

#### Raw schema

Twelve `raw_schema` fields are promoted from `inferred_from_correlation` to
`confirmed`. Each appears in the known-good production rule's alert fields or
XQL, so they are evidence-backed rather than best-effort guesses. The emitted
`_schema.json` grows from 16 to 28 declared fields.

### Verified

On a tenant: the installed rule carries 74 alert fields, zero `proofpointtap*`
entries and three `_raw_json` references; a MITRE Turla Carbon replay produced
both `[Email]` issues with no correlation rule errors, where the rule had
errored on every cycle beforehand; and Email and Endpoint alerts grouped into a
single case.
