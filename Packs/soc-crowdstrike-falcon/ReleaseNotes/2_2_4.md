## [2.2.4] - October 2026

### Fixed

#### SOC CrowdStrike Falcon - Endpoint All Alerts — DNS and remote-IP artifacts restored with real parsing

2.2.3 removed `dns_queries` and `remote_ips` because both were assigned straight
from `dns_requests` / `network_accesses`. Those are arrays of objects, so the
alert fields carried a raw JSON blob rather than a value — for example
`dns_query_name` held
`[{"domain_name":"anto-int.com","request_type":"AAAA",...}]`.

Removing them also removed artifacts XSIAM groups on, and case volume
fragmented: the same user (`gunter@skt.local`) and the same domain
(`skt.local`) ended up split across separate cases that should have been one.

Both are now extracted rather than passed through:

```
| alter dnsa = json_extract_array(to_json_string(dns_requests), "$")
| alter dns_queries = arraymap(dnsa, json_extract_scalar(to_json_string("@element"), "$.domain_name"))
| alter na = json_extract_array(to_json_string(network_accesses), "$")
| alter remote_ips = arraymap(na, json_extract_scalar(to_json_string("@element"), "$.remote_address"))
```

`action_remote_ip` is re-enabled, and `network_accesses` / `dns_requests` go
back into the `fields` clause so the sources survive to the alters.

Five alert fields restored (96 → 101): `dns_query_name`, `dnsqueryname`,
`action_remote_ip`, `remoteip`, `postnatdestinationip`. The two raw
passthroughs (`dns_requests` and `network_accesses` as alert fields) are
deliberately not restored — they carried JSON blobs and are not grouping
artifacts.

Verified on a tenant: the rule now emits `dns_queries = anto-int.com` and
`remote_ips = 176.59.15.33` as clean scalars, a MITRE Turla Carbon replay
produced endpoint alerts carrying `dns_query_name = anto-int.com` where the
field had been null on every alert, and Email and Endpoint alerts grouped into
a single case.

### Known limitations

Grouping remains dominated by `action_file_sha256`. In a representative replay,
130 of 130 endpoint rows carried `sha256`, 22 carried `network_accesses` and 3
carried `dns_requests` — 12 distinct hashes produced roughly 13 cases. A
multi-stage campaign still fragments by binary; restoring these pivots is
necessary but not sufficient to collapse a kill chain into one case.

`soc-crowdstrike-idp` carries the same excise from 1.1.9 and still needs the
equivalent restoration. Its `dst_ip` derivation is additionally mislabeled —
the regextract returns the first IPv4 in the serialized object, which is
`local_address`, not `remote_address` — so it needs more than a copy of this
change.
