## [2.2.5] - October 2026

### Fixed

#### SOC CrowdStrike Falcon - Endpoint All Alerts — `files_written` extracted instead of passed through

`files_written` was mapped straight from the raw column, which is an array of
objects, so the issue field carried a JSON blob rather than a value:

```json
[{"filename":"wmimetricsq.exe","filepath":"\\Device\\HarddiskVolume2\\Windows\\System32","timestamp":"1764719011"}]
```

This is the same defect fixed for `dns_query_name` and the remote-IP fields in
2.2.4; `files_written` was missed in that pass. The filename is now extracted
the same way:

```
| alter fwa = json_extract_array(to_json_string(files_written), "$")
| alter files_written_names = arraymap(fwa, json_extract_scalar(to_json_string("@element"), "$.filename"))
```

The `files_written` alert field now sources `files_written_names`.

Verified on a tenant — the rule returns clean filenames rather than blobs:

```
wmimetricsq.exe
MSSVCCFG.dll, msxhlp.dll, mressvc.dll
well_known_domains.dll, terabox.exe, Microsoft.CognitiveServices.Speech.core.dll
```

This matters for grouping. Of the three array artifacts, `files_written` has by
far the best coverage — 492 of 1560 endpoint rows (32%), against 17% for
`network_accesses` and 2% for `dns_requests`. Dropped-file names also link the
stages of a multi-stage intrusion that distinct `sha256` values otherwise split
apart: the same three DLLs (`MSSVCCFG.dll`, `msxhlp.dll`, `mressvc.dll`) appear
on separate alerts in a Turla Carbon replay, which is precisely the shared
artifact case grouping needs.

Only `$.filename` is extracted, not `$.filepath`. Full paths are more precise
but vary by host and would fragment rather than bind.
